# タスク

@{source_note} の補足リンクと文字起こしを読み込み，以下の 2 つの作業をしてください．

1. ノート内の補足リンクの本文と，文字起こしのトピックとの対応付け
2. 文字起こしの中から外部リンクがあると情報の深みが増す箇所を抽出し，具体 URL を提案

段階 1 の構造化ノートは存在する場合のみ参考にしてください．存在しなくても本タスクは独立して実行できる必要がある．

# 出力先

「[{session_id}]リンク提案」というタイトルで新規ノートを作成し，そこに結果を書き出してください．チャット欄には「リンク提案ノートを作成しました．」とだけ返答してください．

# 出力内容

## メタデータブロック

先頭に以下の YAML 形式のメタデータブロックを記載してください．

```
---
session_id: {session_id}
source_note: {source_note}
stage: リンク提案
generated_at: （生成日時 YYYY-MM-DD HH:MM）
---
```

このブロックは後段の自動処理で参照される識別情報のため，欠落・改変しないでください．

## 補足リンクの対応

| 補足リンク URL | 対応するトピック | 要旨（1〜2 文） |
|---|---|---|

## 追加リンク提案

トピックごとに以下の構造で記載してください．

### トピック（短いラベル）

- 対象箇所：（短い引用または要約）
- 提案 URL：
- 提案理由：
- 信頼度：（高 / 中 / 低 / 不明）

# 制約

- URL は実在性が確認できる公式情報源（公式サイト・公式ドキュメント・公式告知ページ）を優先する．
- 確証が持てない場合は「リンク候補不明」と明記し，URL を出力しない．
- 推測で URL を生成しない．
- 同姓同名や類似名称への取り違えに注意．複数候補がある場合は「要確認」とする．
