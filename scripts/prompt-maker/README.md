# Evernote AI 文字起こし整理プロンプト生成 CLI

Evernote AI へ投入するプロンプトを，セッション識別子から自動生成する Python CLI．
4 段階に分けた Markdown テンプレートへ値を埋め込み，識別子と同名のフォルダへ書き出す．

## 🎯 概要

Evernote AI に対して文字起こしの構造化を依頼する際，
セッションごとに同じ形式のプロンプトを 4 種類入力する必要がある．
本 CLI は，セッション識別子を 1 つ与えるだけで，
4 段階分のプロンプトをファイルとして用意する．

4 段階の役割は以下の通り．

- 段階 1：文字起こしを構造化する
- 段階 2：補足リンクと追加リンク候補を整理する
- 段階 3：固有名詞を校閲する
- 段階 4：文字起こし全文を元ノート本文に貼り付ける（ENEX への保全）

各段階のプロンプトは Evernote AI のチャットへそのまま貼り付けられる．
出力された 4 ノート（または元ノート＋3 ノート）を `.enex` 形式でまとめてエクスポートする．
後段の処理（ブログ執筆素材化など）はこの ENEX を機械的に扱う．

## 🛠️ 前提

- Python 3.10 以上
- 標準ライブラリのみで動作する（依存パッケージなし）
- テスト実行時のみ pytest が必要

## 📁 ディレクトリ構成

スクリプトと同階層に `templates/` を配置する．

```
作業ディレクトリ/
├── generate_prompts.py
├── test_generate_prompts.py
└── templates/
    ├── 01_structure.md
    ├── 02_links.md
    ├── 03_proper_nouns.md
    └── 04_transcript_dump.md
```

実行すると，セッション識別子と同名のフォルダが生成される．

```
作業ディレクトリ/
├── generate_prompts.py
├── templates/
│   └── ...
└── 2026-05-01-他人のルールに乗る/   ← 自動生成
    ├── 01_structure.md
    ├── 02_links.md
    ├── 03_proper_nouns.md
    └── 04_transcript_dump.md
```

## 📥 インストール

リポジトリから `generate_prompts.py`・`test_generate_prompts.py`・`templates/` を取得する．
任意の作業ディレクトリへ配置する．

テスト実行用に pytest を導入する．

```bash
pip install pytest
```

## 🚀 基本的な使い方

セッション識別子を引数として実行する．

```bash
python generate_prompts.py "2026-05-01-他人のルールに乗る"
```

セッション識別子は，元ノートタイトル `[2026-05-01-他人のルールに乗る] 元ノート` の
角括弧内に入れた文字列である．

実行結果は次のように出力される．

```
セッション識別子：2026-05-01-他人のルールに乗る
テンプレート：/path/to/templates
出力先：/path/to/2026-05-01-他人のルールに乗る
生成ファイル：
  - 01_structure.md
  - 02_links.md
  - 03_proper_nouns.md
  - 04_transcript_dump.md
```

生成された 4 ファイルを順に Evernote AI のチャットへ貼り付ければよい．
4 段階は別チャットで実行する想定である（Evernote AI のチャット長制限を回避するため）．

## ⚙️ オプション一覧

表 1: コマンドライン引数の一覧．

| 引数 | 必須 | デフォルト | 説明 |
|---|---|---|---|
| `session_id` | はい | なし | セッション識別子（角括弧の中身） |
| `--output-dir` | いいえ | `./{session_id}/` | 出力先ディレクトリ |
| `--templates-dir` | いいえ | スクリプトと同階層の `templates/` | テンプレートディレクトリ |
| `--source-suffix` | いいえ | `元ノート` | 元ノートタイトルの末尾文字列 |

使用例を以下に示す．

```bash
# 出力先を変える
python generate_prompts.py "foo" --output-dir ./out

# 別のテンプレートを使う
python generate_prompts.py "foo" --templates-dir ./alt_templates

# 元ノートのタイトルが「[foo] 文字起こし」の場合
python generate_prompts.py "foo" --source-suffix "文字起こし"
```

## ✏️ テンプレートの編集

プロンプトを改善したい場合は `templates/` 配下のファイルを直接編集する．
Python ソースに手を入れる必要はない．

各ファイルは通常の Markdown として扱える．
コードブロックや表，リストなどはそのまま記述してよい．

`03_proper_nouns.md` は Evernote ノート `固有名詞マスター` を参照する設定になっている．
このノートが存在しない場合は参照がスキップされる（テンプレート内の「存在する場合」の記述による）．
別のノート名を使う場合はテンプレート内の該当箇所を書き換えること．

## 🔣 プレースホルダ仕様

テンプレート内で利用できるプレースホルダは 2 つだけである．

表 2: プレースホルダの一覧．

| プレースホルダ | 展開内容 | 例 |
|---|---|---|
| `{session_id}` | セッション識別子そのもの | `2026-05-01-他人のルールに乗る` |
| `{source_note}` | `[session_id] suffix` 形式 | `[2026-05-01-他人のルールに乗る] 元ノート` |

`{source_note}` は `[{session_id}] 元ノート` のショートカットである．
`@{source_note}` と書けば `@[2026-05-01-他人のルールに乗る] 元ノート` に展開される．

置換には `str.replace` を使う．
プレースホルダ以外の波括弧（コードブロック内の `{ ... }` など）は保持される．

## 🧪 テストの実行

`code-quality` Skill の TDD 方針に従い，全機能に対するテストを用意している．

```bash
python -m pytest test_generate_prompts.py -v
```

テストは 6 グループで構成される．

- `TestBuildSourceNoteTitle`：元ノートタイトル組み立て
- `TestBuildPrompt`：プレースホルダ置換
- `TestLoadTemplate`：テンプレート読み込み
- `TestGenerateAllPrompts`：段階数分のファイル生成
- `TestValidateSessionId`：セッション識別子の検証
- `TestRealTemplates`：同梱テンプレートを使った統合テスト

プロンプト改善後はテストを実行し，テンプレートの配置漏れや構文崩れを検知すること．

## 🔄 想定する運用フロー

本 CLI は以下のフローを想定している．

```
[Evernote AI で文字起こしノート生成]
            │
            ▼
[ノートタイトルを「[ID] 元ノート」形式に整える]
            │
            ▼
[本 CLI でプロンプト 4 種を生成]
            │
            ▼
[段階 1 のプロンプトを Evernote AI に貼り付け]
            │
            ▼
[段階 2 のプロンプトを別チャットに貼り付け]
            │
            ▼
[段階 3 のプロンプトを別チャットに貼り付け]
            │
            ▼
[段階 4 のプロンプトを別チャットに貼り付け]
            │
            ▼
[元ノート＋3 ノート（または +4 ノート目）を .enex でエクスポート]
            │
            ▼
[後段の自動処理に投入]
```

図 2: 文字起こし整理の全体フロー．

段階 4 は元ノート本文の直接編集を第一候補とする．
編集できない場合は「[ID]文字起こし全文」というタイトルで新規ノートを作成する．

## 🧩 拡張時の手順

新しい段階を追加する場合の手順を示す．

第一に，`templates/` に新しい Markdown ファイルを追加する．
ファイル名は `04_summary.md` のように 2 桁の連番＋スネークケースとする．

第二に，`generate_prompts.py` の `STAGE_KEYS` 定数の末尾に新しいキーを追加する．
ファイル名から拡張子を除いた文字列（例：`04_summary`）である．

第三に，テストを追加する．
`STAGE_KEYS` を参照しているテストは自動的に新しい段階を含めるため，
段階固有の検証だけ追加すればよい．
